OVS-DPDK Troubleshooting

Troubleshooting Steps

Optimizing Memory Channels
  • Identify the CPU model and the number of CPUs installed.
  • Determine how many memory channels each CPU has.
  • Navigate to System → System Information to check RAM DIMMs and slots.
  • Refer to hardware memory guidelines to map slots to channels.
  • Set dpdk-extra: -n N, where N is number of channels with installed DIMM.
MTU-Based Memory Estimation
  1. Round MTU of each NIC on a NUMA node to nearest 1024.
  2. Formula: (ROUNDUP_MTU + 800) * (4096 * 64) bytes.
  3. Calculate per NIC: (9216 + 800) * (4096 * 64) = 2625634304 bytes.
  4. Total with buffer: 2625634304 + 2625634304 + 536870912 = 5788139520 bytes.
  5. Convert to MB: 5788139520 / (1024 * 1024) = 5520 MB → Round to 6144 MB.
  6. Final config: dpdk-socket-mem: 1024,6144 (use 1024 for NUMA Node with no NIC).
Adjusting MBUF Size
  • Default mbuf size is 4096 * 64 — per NUMA node.
  • Run: ovs-vsctl list interface dpdk1 where dpdk1 is your NIC interface.
  • If rx_mbuf_allocation_errors > 0, increase 4096 * 64 in your MTU-Based Memory Estimation formula.
Verify RSS Load Distribution
  • Run: ovs-appctl dpif-netdev/pmd-rxq-show | egrep"pmd thread|dpdk".
  • Analyze PMD and NIC RXQ usage; spot underutilized ones.
  • Uneven spread? May relate to TCP/UDP header presence and traffic patterns.
  • Auto PMD rebalance may happen every few seconds >70% with 25% improvement.
  • The issue can be uneven RXQ traffic. Investigate traffic patterns.
Analyze EMC vs Megaflow Hits
  • Clear stats: ovs-appctl dpif-netdev/pmd-stats-clear.
  • Inspect: ovs-appctl dpif-netdev/pmd-stats-show.
  • High EMC Hits → repetitive flows. Good for performance but can degrade if traffic changes.
  • High Megaflow Hits → >5120 unique flows overflown and performance can degrade.
PMD Thread Performance & Load
  • Check stats: ovs-appctl dpif-netdev/pmd-perf-show.
  • Clear old stats if needed.
  • Review iterations: How active is each PMD thread?
  • Busy 99% indicates over utilized PMDs.
  • Ensure a proper traffic pattern is used for testing.
  • More PMD threads don’t help if traffic isn't well-distributed.
  • Look for idle PMDs — consider adding NIC queues to them.
  • Look for EMC/Megaflow hit % and understand the traffic pattern.
